Основы баз данных и языка SQL
Учебное пособие для студентов

Глава 1. Реляционная модель данных

База данных — это организованная совокупность данных, а СУБД (система управления базами данных) — программа, которая хранит эти данные и обрабатывает запросы к ним. Примеры реляционных СУБД: PostgreSQL, MySQL, SQLite, Oracle.

В реляционной модели данные хранятся в таблицах. Строка таблицы называется записью, столбец — атрибутом или полем. У каждого столбца есть тип данных: INTEGER для целых чисел, NUMERIC для точных десятичных чисел, TEXT или VARCHAR для строк, DATE для дат, BOOLEAN для логических значений.

Первичный ключ (PRIMARY KEY) — это столбец или набор столбцов, однозначно определяющий каждую запись. Значения первичного ключа уникальны и не могут быть NULL. Внешний ключ (FOREIGN KEY) — столбец, который ссылается на первичный ключ другой таблицы и связывает таблицы между собой. Например, в таблице orders столбец customer_id может ссылаться на customers.id.

Связи между таблицами бывают трёх видов: один к одному, один ко многим и многие ко многим. Связь многие ко многим, например между студентами и курсами, реализуется через промежуточную таблицу, содержащую два внешних ключа.

NULL означает отсутствие значения. NULL не равен нулю и не равен пустой строке. Любое сравнение с NULL через = даёт неизвестный результат, поэтому для проверки используют IS NULL и IS NOT NULL.

Нормализация — процесс устранения избыточности данных. Первая нормальная форма требует, чтобы каждое поле содержало одно атомарное значение. Вторая нормальная форма требует, чтобы неключевые поля зависели от всего первичного ключа, а не от его части. Третья нормальная форма требует, чтобы неключевые поля не зависели друг от друга. Нормализация уменьшает аномалии при вставке, обновлении и удалении данных.

Глава 2. Создание таблиц и изменение данных

Таблица создаётся командой CREATE TABLE. Например: CREATE TABLE students (id INTEGER PRIMARY KEY, name TEXT NOT NULL, group_name TEXT, gpa NUMERIC). Ограничение NOT NULL запрещает пустые значения, UNIQUE требует уникальности, CHECK задаёт условие, например CHECK (gpa BETWEEN 0 AND 4), а DEFAULT задаёт значение по умолчанию.

Команда INSERT INTO добавляет записи: INSERT INTO students (name, group_name) VALUES ('Айдана', 'ИИ-201'). Команда UPDATE изменяет существующие записи: UPDATE students SET gpa = 3.5 WHERE id = 7. Команда DELETE FROM удаляет записи: DELETE FROM students WHERE id = 7.

Самая опасная ошибка — выполнить UPDATE или DELETE без условия WHERE. В этом случае команда затронет все строки таблицы. Перед выполнением изменений полезно сначала выполнить SELECT с тем же условием WHERE и убедиться, что выбраны нужные строки.

Команда DROP TABLE удаляет таблицу целиком вместе со структурой, а TRUNCATE удаляет все строки, но оставляет структуру таблицы. Команда ALTER TABLE изменяет структуру существующей таблицы, например добавляет столбец: ALTER TABLE students ADD COLUMN email TEXT.

Транзакция — группа операций, которая выполняется целиком или не выполняется вовсе. Транзакцию начинают командой BEGIN, подтверждают командой COMMIT и отменяют командой ROLLBACK. Свойства транзакций описываются аббревиатурой ACID: атомарность, согласованность, изолированность и долговечность. Классический пример — перевод денег между счетами: списание и зачисление должны произойти вместе.

Глава 3. Запросы SELECT

Команда SELECT выбирает данные из таблицы. SELECT name, gpa FROM students выбирает два столбца, а SELECT * выбирает все столбцы. Условие отбора задаётся в WHERE: SELECT * FROM students WHERE gpa > 3.0.

В условиях используют операторы сравнения, логические операторы AND, OR, NOT, а также специальные операторы. BETWEEN проверяет диапазон включительно, IN — принадлежность списку значений, LIKE — соответствие шаблону. В шаблоне LIKE знак % означает любую последовательность символов, а знак _ — ровно один символ. Например, name LIKE 'А%' выбирает имена, начинающиеся на букву А.

ORDER BY сортирует результат: ORDER BY gpa DESC — по убыванию, ASC — по возрастанию (по умолчанию). LIMIT ограничивает число возвращаемых строк, а OFFSET пропускает заданное число строк — так реализуют постраничный вывод. DISTINCT убирает повторяющиеся строки из результата.

Порядок выполнения частей запроса отличается от порядка их записи. Сначала выполняется FROM и JOIN, затем WHERE, затем GROUP BY, затем HAVING, затем SELECT, затем ORDER BY и в конце LIMIT. Поэтому псевдоним столбца, заданный в SELECT, нельзя использовать в WHERE, но можно использовать в ORDER BY.

Глава 4. Агрегатные функции и группировка

Агрегатные функции вычисляют одно значение по набору строк: COUNT считает количество, SUM — сумму, AVG — среднее, MIN и MAX — минимум и максимум. COUNT(*) считает все строки, а COUNT(столбец) — только строки, где значение столбца не NULL. Функции SUM и AVG игнорируют значения NULL.

GROUP BY объединяет строки с одинаковыми значениями в группы, и агрегатная функция вычисляется для каждой группы отдельно. Например, SELECT group_name, AVG(gpa) FROM students GROUP BY group_name вычисляет средний балл каждой группы. Каждый столбец в SELECT, который не находится внутри агрегатной функции, должен быть указан в GROUP BY.

WHERE фильтрует строки до группировки, а HAVING фильтрует группы после группировки. Поэтому условие на агрегат, например AVG(gpa) > 3.0, нельзя писать в WHERE — его пишут в HAVING: SELECT group_name, AVG(gpa) FROM students GROUP BY group_name HAVING AVG(gpa) > 3.0.

Глава 5. Соединения таблиц и индексы

Соединение JOIN объединяет строки нескольких таблиц по условию. INNER JOIN возвращает только строки, для которых нашлось совпадение в обеих таблицах. LEFT JOIN возвращает все строки левой таблицы, а там, где совпадения в правой таблице нет, подставляет NULL. RIGHT JOIN работает симметрично, а FULL JOIN возвращает все строки обеих таблиц.

Пример: SELECT s.name, c.title FROM students s JOIN enrollments e ON e.student_id = s.id JOIN courses c ON c.id = e.course_id. Здесь s, e и c — псевдонимы таблиц, которые сокращают запись.

Чтобы найти записи без пары, например студентов, не записанных ни на один курс, используют LEFT JOIN и условие WHERE e.student_id IS NULL. Если забыть условие ON или указать его неверно, получится декартово произведение: каждая строка одной таблицы соединится с каждой строкой другой, и результат станет огромным.

Подзапрос — это запрос внутри другого запроса. Например, SELECT name FROM students WHERE gpa > (SELECT AVG(gpa) FROM students) выбирает студентов с баллом выше среднего.

Индекс — это дополнительная структура данных, которая ускоряет поиск строк по значению столбца, подобно предметному указателю в книге. Индекс создаётся командой CREATE INDEX idx_students_name ON students (name). Индексы ускоряют чтение, но замедляют вставку и обновление, так как индекс тоже нужно обновлять, и занимают дополнительное место. Поэтому индексы создают на столбцах, по которым часто ищут, сортируют или соединяют таблицы. Первичный ключ индексируется автоматически.

Для защиты от SQL-инъекций нельзя вставлять пользовательский ввод в текст запроса через склейку строк. Нужно использовать параметризованные запросы, в которых значения передаются отдельно от текста команды, например cursor.execute('SELECT * FROM users WHERE login = ?', (login,)).
